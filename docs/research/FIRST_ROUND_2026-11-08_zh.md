# 多来源 TE 注释：首轮研究推进方案

版本：A0.3；日期：2026-11-08。状态：实施计划，尚未实现或验证新的概率推断能力。本文承接 2026-11-07 的 A0.2 算法选型，将其收敛为第一轮可执行工作。TEflow 的生产注释、选库与软屏蔽接口保持现有语义。

## 1. 本轮要回答的核心问题

**在可追溯、存在派生关系的 TE 注释来源中，能否用有限的已审计标签，获得比简单证据模式表和普通正则 logistic 更可靠的候选位置概率，并明确知道何时不能判断？**

首轮目标是建立证据与评价闭环，完成小规模统计原型。先用拟南芥；水稻用于下一步资源审计与外部验证准备。衣藻、Klebsormidium nitens、地钱保留为后续迁移对象，不要求同时重跑五个物种。

算法选型继续采用：

- **DS-EM：必做基线。** 同时保留无锚点和同锚点辅助版本。
- **独立贝叶斯分类器共识（IBCC）：第二个生成模型基线。** 用于检验参数不确定性与先验敏感性，不预设已经解决来源依赖。
- **主候选：来源感知、锚点辅助的低维贝叶斯 logistic 条件融合。** 同特征的普通正则 logistic 和联合模式 Beta–Binomial 是强制对照。
- 无可信正、负锚点时，交付来源审计、模拟、分歧与复核队列，不把无监督共识数字称为已校准正确率。

这里的“锚点”是已有审计依据的训练标签，不是多数票制造的标签。主模型是参考辅助的条件预测，不是完全无监督 DS/BCC，也不直接估计各工具的真实灵敏度、特异度。

这一选择符合已有方法的限制：DS 是潜类别误差模型；IBCC 仍有独立性设定；已有依赖 BCC 和依赖分类器方法并不保证在少数高度相关来源下可识别。贝叶斯先验和 MCMC 不会增加原本缺失的信息。[DS 原文](https://crowdsourcing-class.org/readings/downloads/ml/EM.pdf)、[Kim–Ghahramani BCC/DBCC](https://proceedings.mlr.press/v22/kim12.html)、[Simpson 等 IBCC](https://arxiv.org/abs/1206.1831)、[Jaffe 等依赖分类器](https://proceedings.mlr.press/v51/jaffe16.html)。

## 2. 与 v4 发布和既有数据的衔接

v4 CPU 默认、v3 显式备用的封装已通过有限服务器验收。新生产适配器尚未重新完成整套基因组运行；实际全基因组证据来自先前的实验性桥接。52 个 v3 独有 hAT 位置在 v4 初始 GRF 中存在、后检查点消失，仍不能区分 CNN 与结构规则的具体责任，更不能自动标为漏检真值。[实际验收记录](../TIR4_SERVER_REVIEW_2026-11-08_zh.md)

研究数据分成明确的三个版本，禁止静默混拼：

| 数据包 | 用途 | 约束 |
|---|---|---|
| 已完成的 `at_v06_parallel` 全分支包 | 第一轮导出器、坐标、派生关系与模式统计开发 | 保留其当时的 TIR 版本，明确是历史输入，不改称 v4 结果 |
| 已完成的 v3/v4 TAIR10 配对实验 | 版本敏感性与 hAT 案例诊断 | v3 与 v4 是替代算法版本，不能当成两个独立投票者；已有 59 位点仅作定向案例集 |
| 待组装的 v4 主研究包 | 后续正式拟合及留出评价 | E4 与从它实际生成的 ET4 配对；I/H 的基因组、分析范围、映射参数及来源记录需逐项匹配 |

**不能用 E4 替换旧 E，再把 ET3 写成 E4 的后代。** 这是当前比更复杂的共识公式更优先的数据问题。

第一步先清点服务器已有库和完整结果。如果实验 E4 库及映射结果具备可核验的运行回执，开发只读研究导入器即可复用；需要补 ET4 时只执行必要的 TEtrimmer 和统一映射。I 的库也可在核对后复用并重新统一映射，不因研究模块开发而重跑 HiTE。只有缺失或不兼容的部分才重新计算，且进入新目录。实验导入不伪造生产阶段完成回执。

本次只准备方案，不启动上述服务器计算。历史数据闭环可先推进，不必等待一个新的全分支基因组任务。

## 3. 推断量与输入来源

首轮估计：

\[
q(x)=P(Y_b=1\mid X_b=x,\ b\in\mathcal C,\ profile),
\]

其中 b 是候选集合内的一个基因组位置，Y 表示该位置具有可辩护的 TE 来源。它不是完整插入存在概率、精确边界概率或全基因组漏检率。一个区段共用一个 q，也不表示“整个区段全部正确”的概率。

TE 来源与是否应软屏蔽分开：明确来自 TE 的宿主驯化片段可记录其来源，同时单列使用状态；证据不足的古老同源、宿主捕获或混合边界保留未解决，不用 CDS 重叠替代裁决。

### 3.1 首个 profile：core

使用完成的 E、ET、I 三个来源。每个来源的命中范围为其已分类 TE 与 Unknown 命中的并集；明确的 simple repeat、low complexity、satellite、RNA 等不因存在 RepeatMasker 行就自动进入 TE 候选。保留原始类别及排除原因；TE 与这些层重叠时不直接删去 TE 证据。

\(\mathcal C = C_E\cup C_{ET}\cup C_I\)。只在三者都成功且可比较的分析范围内建立 core。Unknown 保持“类别未解决”，不当作非 TE 标签。

| 来源/记录 | 主模型中的角色 |
|---|---|
| E 与 ET | 联合位置命中状态 `00/10/01/11`；记录 E→ET 父子关系 |
| I | 独立输入列，但不声称与 E 条件独立；保留捆绑模型/同源资源信息 |
| H 原始结构位点 | 下一 profile 的增量证据；不能以清理后库反推原始 H=0 |
| H 清理库 | 来源诊断；记录 EDTA 辅助清理关系 |
| EH | 组合库及竞争映射的对照，不作为新的独立投票 |
| R 参考库 | 参考使用台账及独立参考辅助实验，不混入主模型后再用同库评价 |
| v3/v4 输出 | 版本敏感性分析，不叠加为票数 |
| TRF/DUST、宿主蛋白证据、分类冲突 | 首轮分层诊断，暂不加入主模型或当成真值 |

`core+H` 只有在原始 H 位点与成功完成范围可核对时启用。增加 H 会改变候选集合，因此既报告各 profile 的实际范围，也在固定的共同候选并集上单列增量比较。不能把新增候选收益全部归因于概率模型。

### 3.2 状态合同

保留 `NOT_RUN / FAILED / OUT_OF_SCOPE / NO_HIT / HIT_UNRESOLVED / HIT_CLASSIFIED`。`NO_HIT` 仅表示在成功完成的可检测范围内未报告命中，不是真阴性。缺少必需来源时返回 `UNSUPPORTED_PROFILE`，不补成零继续套用 core 模型。

ET 的 `refined / fallback / low_copy / no_retained_descendant` 另存为派生状态。某 E 家族没有后代，不等于它覆盖的所有位置都是假阳性；`E=0,ET=1` 也可能是精修后新增映射，不能当成非法状态。

## 4. 第一批数据合同与可复用文件

所有研究产物写入独立目录，记录 `schema_version / protocol_id / producer_version / dataset_id`；原始工作目录只读。

| 产物 | 最小内容与用途 |
|---|---|
| `dataset.json` | 组装、核染色体范围、输入运行、工具/数据库/模型版本、RM 参数、坐标映射、完成状态、缺失项 |
| `sources.tsv`、`source_edges.tsv` | 来源节点及 `derived_from / refined_from / exact_alias / shares_resource / combined_from / remapped_with` 关系；不是学出的概率图 |
| `raw_hits.tsv.gz` | 原始记录 ID、标准坐标、来源、库条目、原始/标准类别、原始分数及含义 |
| `segments.tsv.gz` | 排序后的不重叠证据区段、长度、证据模式、可用 profile；区间均为 BED 半开坐标 |
| `segment_evidence.tsv.gz` | 区段与原始命中的多对多关系、原始类别/父条目；记录切分后仍能回查 |
| `pattern_counts.tsv` | 各模式区段数、碱基数、类别分层、缺失状态；用于抽样而非准确率结论 |
| `label_use.tsv` | 真值/银标准的来源、许可、曾否用于上游训练/分类、train/dev/test 角色、已知与未知污染风险 |
| `audit_sample.tsv`、`audit_labels.tsv` | 采样概率、随机种子、区块/同源组、盲审标签、支持证据、未解决原因 |
| `diagnostics.json`、`REPORT.md` | 不变性、模式支持、数据缺口、数值与评价状态；缺失证据不得写成通过 |

当前 TEflow 输出可提供 `mask_sources.tsv`、`te.mask.bed`、`repeat_unknown.bed`、`family_provenance.tsv`、`parents.tsv`、库 FASTA，以及 `heliano/native_sites.tsv`。具体以当前输出合同及实际文件为准。[输出指南](../RESULTS_GUIDE.md)

完整的 `genome.fa.out` 可用于坐标/类别交叉检查。`.align` 对主二分类模型不是必需；它只在详细边界、竞争比对或 AURORA 对照时成为额外输入。基因组保留在服务器，首轮本地导出无需复制各分支巨大软屏蔽 FASTA。GFF3/蛋白序列用于可选审计，不是开启概率模型的硬依赖。

### 表示算法的约束

按端点扫描构造原子区段，使用每个来源的**活动命中计数**后再取是否大于零，正确处理同一来源内部的重叠。复杂度按命中记录/端点计，不展开全基因组逐碱基矩阵。相邻且模型证据完全一致的区段可合并；原始记录和类别变化另留关联表。

相邻区段、重复拷贝与同源家族不是独立样本。区段长度用于总体覆盖与抽样权重，不能当作标签似然的重复次数。拆分一个原始命中或复制同一来源文件，不能增加独立审计标签数或使后验更窄。

## 5. 模型实现阶梯与消融

### 5.1 必须实现的对照

| 模型 | 输入/标签 | 要回答的问题 |
|---|---|---|
| 单分支、并集/交集、来源整理后的投票 | 同一候选范围；硬决策另报 | 简单策略已能做到什么 |
| 单分支/投票的校准版本 | 与主模型相同训练标签 | 不让概率模型仅因拿到更多标签而获胜 |
| 联合模式 Beta–Binomial | 每种 E/ET/I 模式的已审计正负标签 | 直接记住模式概率是否已经足够 |
| DS-EM | 无锚点 + 同锚点两条实验 | 条件独立潜类别基线的适用与失败情况 |
| IBCC | 与 DS 同来源、同标签制度 | 先验与参数后验带来什么，不冒充依赖处理 |
| 正则 logistic | 与主模型相同特征和标签 | 贝叶斯实现是否值得其复杂度 |
| 主模型及有限消融 | 同一标签划分、候选范围和计算预算 | 派生状态与预设交互的增量价值 |

DS 先与 [Crowd-Kit 官方实现](https://github.com/Toloka/crowd-kit/blob/main/crowdkit/aggregation/classification/dawid_skene.py) 在小型已知答案上交叉核对，不照搬其数据接口来掩盖失败状态。DS/IBCC 的实际拟合对象是按已冻结设计抽样的位置，不把所有原子段或所有碱基当成独立重复观测。

### 5.2 主模型

令 \(g=(e,t)\)，令 i 表示 I 的命中。core 使用：

\[
\operatorname{logit}(q_u)=\beta_0+a_{g_u}+\beta_I i_u+\gamma e_ui_u,
\qquad a_{00}=0.
\]

共 6 个系数。core+H 另加 \(\beta_H h_u\)，共 7 个。H=0 是同一已运行 profile 内的基准状态，不编码成对所有 TE 类别的反对票。只预设一个 E×I 交互，不搜索全部交互图。

消融依次为：`E+ET+I` 加性 4 系数 → `E/ET 联合状态 + I` 5 系数 → 增加 `E×I` 6 系数。每一步固定标签、抽样和候选集合，明确增加了函数自由度。联合状态与 `E×ET` 交互编码等价；这一重参数化本身不是新算法，也不证明“恢复了真实依赖图”。

主模型先验起点沿用 A0.2：截距 N(0,2.5²)，联合状态和 I/H 主效应 N(0,1.5²)，E×I 交互 N(0,0.5²)。比较这些标准差的 0.5、1、2 倍并做先验预测检查，开发完成后冻结。比较不同编码时检查诱导先验，不能把编码变化带来的先验变化误说成单独的表示收益。

先用 MAP 核对实现，再对少量系数作 CPU 后验采样。建议从 4 链、每链 1,000 预热 + 1,000 保留开始；目标为 R-hat≤1.01、关键概率的 bulk/tail ESS≥400、无发散。未达到时报告数值未通过并诊断，不能把增加迭代次数作为解决不可识别的证明。采样预算在开发集可调整，测试前固定。

所有可出现的 core 模式至多 7 个；模式表本身已非常灵活。主模型的实际价值可能只是稀疏模式间的合理共享，必须允许结果支持更简单的算法。设计矩阵实际秩、缺失模式、分离及先验敏感性逐次报告；未见模式不自动获得可部署置信度。

### 5.3 候选筛选与观测复制

总体中条件独立的来源，经过“至少一方命中”筛选后也可能相关。普通 DS/IBCC 在候选内的乘积拟合明确标为近似基线；模拟中增加选择归一化的公平性检查：

\[
P_\theta(O=o\mid S=1)=
\frac{\sum_y\pi_y f_y(o)}{P_\theta(S=1)},\quad s(o)=1.
\]

固定完整 O 和参数时，S 是 O 的函数，不改变该条件下标签后验；需要修正的是用筛选数据估计参数的似然。主条件模型直接针对候选内的 q，不估计全零区域的类别比例。

同来源副本先在来源层折叠。未知的近似相关来源只登记和做敏感性实验，不能任意合并为“完全同一个来源”。无标签位置可提供模式频率和支持范围，不能加入主模型的标签似然来制造大量确定性。

## 6. 标签与评价：首轮最大的实际约束

先明确审计手册，再开始抽样。判定依据应可追溯，允许 `TE_SUPPORTED / NONTE_SUPPORTED / UNRESOLVED`；边界未解决另记。核酸/蛋白同源、终端结构和上下文可以支持判读，但如果来自被测工具共享的同一资源，需要标为相关证据。精校库 remap 先视为参考或银标准，不能天然充当独立真值。

### 首批抽样

建议开发先导预算为 core **每个实际存在的非零模式 20 个位置，最多 140 个**。这是工作量起点，不是样本量充分性保证。在每个模式覆盖的候选碱基中无放回随机抽样，固定种子，记录总体碱基数、纳入概率及空间/家族关系。审计时查看上下文，但一个抽中位置仍只贡献一次标签。

另列最多 30 个定向困难案例，包括已有 hAT 分歧、Unknown、低复杂度与宿主重叠；它们用于解释和压力测试，不能混进代表性概率评价。第一批不要求用户下载新的全基因组数据。

先导样本全部作为开发材料，不作为封闭测试。随后依据可裁决率、模式内正负覆盖、相关性和学习曲线决定是否追加约 200–400 个位置及独立测试预算；数字不能替代功效/精度评估。只挑明确正例会使虚假阳性和概率校准无法评价。

审计者尽可能不知道融合预测与方法优劣结论；保留审计证据来源、意见与未解决原因。只有一位审计者时标记单人审计。未解决率按模式报告；若难例更常无法裁决，已裁决子集的校准不能外推为全部候选的校准。

### 划分与主终点

主终点：冻结测试集上、以候选位置总体为目标的抽样加权 Brier score；同时报告未加权结果、区段/模式构成、可裁决率和置信区间。权重为抽样纳入概率的倒数；先导中的额外困难案例不加入总体估计。

训练使用未加权条件似然仅在抽样只依赖模型已条件化的特征，且裁决缺失可忽略时合理。偏离这些条件时应重新设计抽样或明确采用加权伪似然和敏感性分析；不要把后者产生的区间称为普通独立抽样后验。

以空间块留出作为首个划分，并单独做同源家族留出的敏感性分析；同一物理候选及同源记录不能随机拆到训练和测试。空间与家族是交叉相关结构，不将两个 ID 拼接后就宣称独立。所有方法使用同一组划分，配对比较，并报告两种分组重采样的结果；区块数不足时不宣称有精确总体区间。

次终点为 log loss、可靠性图、共同覆盖率下的选择性风险、复核错误富集及 CPU/内存。并集在自身候选范围内全部为阳性，作为透明的硬决策基线，不冒充有排序能力。测试后挑出的最佳单工具只能标为 oracle。

不能对只保留“有信心”的样本计算 Brier 后与全覆盖基线直接比。主概率评分覆盖预先指定且各模型共同可评价的测试集合，同时报告不支持的比例；拒判收益在单独的风险–覆盖曲线上比较。

## 7. 模拟、工程不变性与 Go/No-go

先做表级模拟，再做昂贵的序列级半合成。每种场景固定参数范围、随机种子和重复次数，初始可用 100 个重复、每次 2,000 个候选；数值只是可调整的先导预算，冻结前记录版本。

| 检查 | 具体操作 | 验收意义 |
|---|---|---|
| 来源复制 | 将同一来源登记为副本 1/2/5 次 | 折叠后证据及 MAP 预测一致；采样差异不超过其 Monte Carlo 误差 |
| 记录切分 | 将一个命中拆为多个相邻片段；加入重复行 | 候选覆盖/位置证据与审计单位不变，不能扩大标签样本量 |
| 状态异常 | 必需分支失败、缺失、合法零命中、范围不符 | 失败/缺失不被补零；非法 profile 明确拒绝 |
| ET 派生选择 | 有依赖的保留、精修和新增映射 | 检查是否把策展未保留误当非 TE 真值 |
| OR 候选截断 | 先生成总体，再筛选有命中位置 | 对照普通与选择修正生成似然，记录误设/识别不足 |
| 共享难度与错误 | 按退化/低复杂度等潜在难度共同犯错 | 不只按主模型公式生成有利数据 |
| 锚点偏倚与稀疏 | 减少负例、整种模式无标签、难例更常未裁决 | 识别外推/先验驱动，不能维持虚假的高置信结论 |
| 版本替换 | E3→E4，连同真实后代 ET 同步改变 | 属分布变化与迁移测试，不计新增选票 |

序列级半合成置于真实植物背景上，只为植入对象建立明确真值；原生背景不能全部标负。它需要重新跑上游，安排在表级合同和模型通过之后，首批不立即开展。

**工程 Go：** 坐标和覆盖交叉核对通过、派生图可追溯、完成/零命中语义正确、复制和切分检查通过，且没有把旧 ET 配给新 E。

**模型 Go：** 有足够可辩护正负标签、主要模式可评价、数值诊断通过；相较同标签的模式表及普通 logistic，主方法在封闭测试中达到预先冻结的实用改进。最小 Brier 改进及风险容忍度在先导后、测试标签开启前写入 `evaluation_protocol.json`；本方案不把任意 1% 当成生物学意义阈值。

**收敛/停止：** 简单模式表或普通 logistic 同样好，就采用简单模型；可靠标签不足就先做审计组件；收益只来自标签数量或重复证据，停止“依赖建模改进”的主张。无统计优势但能稳定改善复核效率，可另评估诊断工具价值，不预定独立方法论文一定成立。

## 8. 第一轮开发工作包

下列为计划工期，标签审计与服务器补算可能延长，不是论文完成期限。

| 顺序 | 大致工作量 | 交付物 | 完成门槛 |
|---|---|---|---|
| P0：来源清点与输入冻结 | 1–2 个工作日 | 历史 core 数据清单、缺口与 v4 配对补齐计划 | 清楚哪些是现成数据、哪些必须补算 |
| P1：只读证据适配 | 2–3 日 | 来源图、区段表、模式统计、坐标/状态测试 | 三个来源与原输出逐分支覆盖核对；复制/切分不变 |
| P2：标签手册与抽样 | 1–2 日，另计人工审计 | 140 位置先导计划、盲审模板、标签用途台账 | 不能用无命中、v3 或参考 remap 自动制造负/正真值 |
| P3：模拟与基线 | 2–3 日 | 规则、模式表、DS、IBCC及选择诊断 | 已知答案与失败场景均可复现；不需要真实标签就能先做 |
| P4：主模型与评价冻结 | 2–3 日，需可用标签 | MAP/后验、匹配消融、学习曲线、冻结评价协议 | 无标签时停在模拟/审计结果，不伪造真实校准 |

第一轮通常是约两周的工程原型，加实际标签审计时间。第一批代码应先完成 **P0/P1/P2 的模板和 P3 的模拟**，并交付一份数据可用性报告；不一开始投入 HMM、任意依赖图或全物种发现。

## 9. 与 TEflow 的工程隔离

生产侧先只增加只读导出合同；研究原型采用独立代码包/环境与协议版本，分为 `evidence / sampling / models / diagnostics / evaluation`。未来是否公开成可选子命令由原型验收决定，本计划中的文件名不是已经存在的 CLI。

- 研究统计依赖不得成为普通 TEflow 安装的强制依赖；CPU 足够支持低维模型。
- 研究入口接受显式完成结果清单，不能通过导入生产调度器内部对象获得隐式状态。
- 数据缺失报错/标记，不能自动启动 EDTA、修改数据库或恢复一个旧冻结任务。
- 输出 `profile / candidate_scope / evidence_pattern / p_mean / p05 / p95 / support_status / probability_status / review_reason / source_ids`。分位数只描述指定模型下 q 的后验，不表示真实 0/1 标签落入区间的频率保证。
- 推断结果单独保存，不覆盖现有 BED、GFF、库或 softmasked FASTA；`select` 继续要求用户明确选择。
- 只公开代码、协议、合成夹具和可公开的小型结果。基因组、数据库、完整日志与服务器路径仍留在运行目录。
- 延续无手工源码/上传 SHA256 验证的约定；Git 提交和内部科学来源记录仍用于辨别版本。外部资源下载按发布方校验方式处理。

## 10. 创新主张与本轮检索边界

依赖共识、贝叶斯标签模型、TE 证据整合和 TE 注释置信度都有先例。BAYSIC 已将无金标准潜类别融合用于基因组变异；AURORA 官方接口接收比对与评分矩阵进行注释裁决，不能仅凭 README 就断言它局限于单库。因此当前不写“首个贝叶斯 TE 注释工具”或“首次解决依赖”。[BAYSIC](https://link.springer.com/article/10.1186/1471-2105-15-104)、[AURORA 官方仓库](https://github.com/TravisWheelerLab/aurora)、[TE 亚家族置信度研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC7827986/)。

值得检验的贡献是：**把 TE 的派生来源、候选筛选与记录表示放进可审计的概率使用协议，并在同信息量对照、代表性审计和版本变化下证明可靠性或复核效率的收益。** 这是一项待验证的组合方法贡献假设，不是理论或新颖性已成立的结论。

本轮定向复核了 DS、BCC/IBCC、依赖分类器、可识别性及 AURORA 官方入口；普通网页检索未形成系统性文献穷尽，不据此证明不存在类似实现。此前可识别性警惕仍成立，相关条件应按原论文使用，而非仅数工具个数。[Allman–Matias–Rhodes](https://arxiv.org/abs/0809.5032)。

进入论文型开发前，需进一步审查 AURORA/PolyA 的实际代码与近期论文，并判断是否值得按相同问题复现一个真正的依赖 BCC 对照；第一轮没有完成该比较，不能声称优于这些方法。
