# TEflow 0.6.0 本轮交付与下一步路线

本轮已按你的调整，将开发重点收敛到**单物种流程、单物种多个库的并行和 GitHub 工程化**。多物种队列暂缓。0.6.0 是本轮单物种工程包的版本号，并不表示 Claude 原建议中多物种及生产 systemd 后端的所有里程碑都已完成。

## 已完成的改动

| 方面 | 0.6 的实现 | 对现有工作意味着什么 |
|---|---|---|
| 单物种多库并行 | 保留一个 Snakemake DAG；阶段级 CPU/内存/I/O 申报；默认串行、显式启用并行 | 不需要外层另写多个库循环，也不把每个分支当成独立物种任务 |
| 资源管理 | 项目级单控制器锁、原子租约、不同 CPU 集合、独立 TMPDIR、内存准入与采样 | 避免本项目分支争用同一组核；保留内存超申报标记和阻塞原因 |
| 失败处理 | 独立分支继续；依赖失败的分支标记阻塞；最终整体仍失败 | 不因某一可选工具失败丢弃其他库的已完成输出，也不误报全部完成 |
| 分类归一化 | 显式、版本化的 0.3 词表；修正 MULE/CMC 等 RM 命名；保留原名、未知子类和不确定标记 | 跨工具分类汇总更一致，不修改实际序列或基因组掩蔽区间 |
| 共识坐标 | 保存原始 tokens、标准化起止、剩余长度、库长度和诊断标记 | 可审计坐标；不再用一条未经真实数据支持的不变式阻断导出 |
| GFF3 | 仅给通过检查的记录添加 Target；反链命中由第七列表示，Target 保持共识正向 | 避免双负号导致相对方向解释错误；不凭 `.out` 杜撰 Gap |
| 物种属性 | HiTE 根据 taxon_group 设定 --plant；旧配置缺省仍为 plant | 为通用基因组流程保留明确入口，不将拟南芥参数隐式推广到所有类群 |
| 覆盖与掩蔽 | 分层 union 汇总；默认主掩蔽保持不变；新增显式 Unknown-inclusive FASTA/BED | 可用于普通基因组注释，也能为其他下游提供不同掩蔽策略 |
| 旧结果重评估 | `audit-results`、`reevaluate`；新目录记录来源与新表格 | 不重跑旧发现流程，不改写旧库、旧注释或冻结记录 |
| I/O 与发布 | 大文件内部身份缓存；启动器集中 freeze；reflink/copy；状态查询只查元数据 | 减少重复读取；源码、上传和反馈不再要求 SHA-256 验证步骤 |
| GitHub 工程 | source/wheel/sdist、CI、文档索引、维护边界、单命令服务器模拟验收 | 可进入仓库同步前的最终服务器验收；本轮没有 push、tag 或公开发布 |

## 对 Claude 建议的取舍

采纳了分类映射、共识坐标、taxon_group、coverage_layers、可选掩蔽、离线重评估、减少重复读取和注册表等核心建议。运行资源层提前落实到单物种多库，而不是先实现多物种大框架。注册表先统筹分支依赖和探针，不为目录形式整齐大规模搬动已工作的适配器。

以下几点做了实质调整：

- **不把共识坐标等式作为强制全局门槛。** 对已有五个拟南芥 `.out` 文件及所提供库组合共检查 138,742 条记录，有 4,975 条坐标或长度诊断记录。实际还存在负数剩余长度。原因不能仅从字段推断，可能需要核对对应生产文件和原始比对。因此保留证据、标记异常、禁止无依据的 Target/完整拷贝推断，同时保留有效的基因组区间。
- **不用硬链接暂存可被上游改写的输入。** 只读位不能可靠阻止文件所有者改回权限；独立 inode 的 reflink 或 copy 更适合此处。
- **内存观测与硬限制分开交付。** 当前 CPU 亲和分配会实际约束可用核，内存申报负责准入，RSS 负责观测；后者不是 cgroup 硬限制。先完成目标服务器单物种并行验收，再考虑把此前 B2 验证过的 systemd 基础部件接入生产。
- **B3 不再阻塞本轮。** 原严格零会话证据仍记为未证明；closing 会话单独展示，不终止共享账号下的其他工作，也不把“心跳还活着”直接改成完整 B3 通过。
- **分类不凭空补齐。** 能确认根类别、不能确认超家族的原名保留为 root_only，不伪造精细分类，也不把它自动降为生物学 Unknown。

## 测试范围

最终机器记录位于 `docs/validation/local_v0.6.json`，详情见 [TEST_STATUS_v0.6.md](TEST_STATUS_v0.6.md)。测试区分：便携单元测试；Linux 实际进程/资源测试；真实 Snakemake 加模拟上游工具；已提供真实输出的只读解析；安装后的包行为。它们不能互相替代，更不构成多物种精确率/召回率验证。

并行验收特意执行串行与并行两套同样的合成流程，比较库、BED、GFF3、主/可选软掩蔽 FASTA 及分类表；再故意使 HiTE 分支失败，检查 E/ET 能继续完成、HiTE 后代被阻塞、最终结果不误报成功。另一组测试检查内存不足时不启动任务、控制器互斥、租约释放、子进程超时清理、不可读身份不被当作进程已死。

真实数据审计只读，使用你已提供的 E、ET、H、I、EH 文件；没有启动新的 EDTA、TEtrimmer、HELIANO、HiTE 或 RepeatMasker。完整服务器内的配套文件关系仍应再用 `audit-results` 核对。不是看到诊断数字就要求重跑。

## 下一步只推进三件事

1. 按 [SERVER_v0.6_zh.md](SERVER_v0.6_zh.md) 解压并执行短模拟验收，回传自动生成的 feedback 包。
2. 对旧 `at_compare_v022` 执行独立审计和重新评估，观察分类修正的实际影响，并确认库与 `.out` 的对应关系。
3. 在上述反馈通过后，选择一组真实的独立 RM 分支测量并行时间、采样 RSS 和磁盘占用。再据此制定可复用资源配置；不把数百 GiB 总内存直接当成本任务可独占预算。

后续尚未定型的是生产 cgroup 硬限制、控制器重启接管、跨多日退出登录保证、多物种调度和跨物种生物学验证。这些保留独立接口和证据要求，暂不扩大到本轮的默认路径。已有发现算法、库合并规则、可选参考分支及 HELIANO 补充证据策略继续沿用；pCRE 不参与核心调度和默认库选择。
