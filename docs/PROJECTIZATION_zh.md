# 0.4.0：从已完成验证转向 GitHub 工程化

本次保留现有发现工具、库合并和候选审核协议，将开发重点转为命令、安装、升级、文档和验证接口。核心用于通用 TE 注释与基因组注释；pCRE 继续作为可选下游用途。

## HELIANO 的当前定位

拟南芥 H 分支已完成，产生 233 条代表序列，其中 231 条有 RepeatMasker 命中；H 覆盖并集为 3,347,967 bp。E+H 相对 E 新增覆盖 1,235,499 bp，同时有 4,155 bp 的 E 覆盖未保留，因此净增加为 1,231,344 bp。这里的数量是代表序列数和比对覆盖量，不能直接解释为经过确认的 TE 家族数或新 TE 真值。

它的补充价值明确存在，但部分候选涉及宿主基因片段、低复杂度和不清楚的内部/末端边界。H 使用 EDTA 辅助清理，所以不作为独立全 TE 基线。继续保留 H 与 EH 的独立产物、QC 和来源记录；当前只做同分类全长精确/反向互补别名折叠，不增加自动优选或近似合并。

最新选定位点的服务器复现通过：16 条命令完成，18 项科学输出与本地逐字节一致，5 张汇总表可从原始输出重新计算。这证明这项局部检查可复现，不能据此给 HELIANO 全局准确率。详细记录见 [HELIANO 状态](HELIANO_STATUS_2026-10-16.md)。剩余候选的生物学判定不再阻塞工程发布。

## 已实现的工程边界

| 需求 | 0.4.0 实现 |
|---|---|
| 任意基因组建立项目 | `teflow init` 接受真实 FASTA 路径与样本 ID；基因注释可选 |
| 统一常用命令 | `plan → check → run --dry-run → run → status` |
| 恢复与分支运行 | `run --resume`、`--target-stage`，保留锁与输入一致性检查 |
| 可审计升级 | `fork-config` 保留原科学参数，绑定新 wrapper 路径，记录迁移旁文件 |
| 脱离源码运行 | wheel 包含 Snakefile、运行脚本与环境配方，并统一资源定位与散列 |
| 后续扩展 | `capabilities` 报告接口版本/验证范围；开发文档约定 adapter、输出、版本和测试责任 |
| GitHub 管理 | CI、分发包构建检查、issue/PR 模板、贡献规范和发布步骤 |

`check` 不冻结；修复依赖后可重新验收。`run --dry-run` 会冻结并检查依赖/DAG；不是纯只读，也不意味着已完成基因组分析。旧 `run_server.sh` 仍可用，其运行规则委托给同一个 Python 启动器。工具环境、数据库、基因组不打进 wheel。

## 现有服务器下一步

无需重装已经验收的上游环境，无需为这次工程更新重跑 EDTA/TEtrimmer/HELIANO。把 0.4.0 源码包解压到一个新目录，按 [UPGRADING](UPGRADING.md) 核对版本并运行 `tests/integration_cli.py`。这只是小型合成数据与模拟上游工具的命令验收，使用真实 Snakemake。

现有 v022 生产结果、0.3.0 蛋白审核与 0.3.1 边界审核保留其原版本。新的代码指纹不能就地接管这些 frozen 运行。未来需要新项目时用 `init`；需要保留旧自定义配置时用 `fork-config`。它不会自动导入或重算旧阶段。

新项目安装与数据库步骤见 [INSTALL](INSTALL.md)，所有新命令的作用见 [COMMANDS](COMMANDS.md)。源码中的历史修复说明仍保留为证据，不作为首次安装的连续步骤。

## 发布与后续范围

当前已整理为 GitHub 项目结构，远程仓库尚未创建或推送；也没有宣称远程 CI 已通过。确定仓库归属、可见性及真实作者信息后，可按 [GITHUB_RELEASE](GITHUB_RELEASE.md) 发布。包里不写虚构的 owner、DOI 或成功徽章。

后续优先处理实际安装反馈、配置/输出格式的版本说明与少量外部调用示例。新增 TE 工具、复杂自动合库或未决候选的全量生物学鉴定，均可以独立排期，不作为本次 GitHub 工程化的前提。可插拔第三方 SDK 暂未实现；当前预留的是明确的内部扩展契约，不把一个未测试的动态插件系统暴露给用户。
